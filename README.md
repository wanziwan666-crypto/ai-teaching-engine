# Math Tutor 🧭

> AI 家教五步教学术——讲→练→诊断→干预→复盘，零依赖 AI 辅导引擎

给它任何一道数学题，它不会直接给答案，而是用五步循环把孩子**教到懂**。

## 五步教学法

```
讲（EXPLAIN）→ 练（PRACTICE）→ 诊断（DIAGNOSE）→ 干预（INTERVENE）→ 复盘（REVIEW）
```

| 步骤 | 做什么 | 核心原则 |
|------|--------|---------|
| 讲 | 一步步引导提问 | 绝不给答案，每步只问一个问题 |
| 练 | 分步出题收集过程数据 | 拆成和讲解一样多的步骤 |
| 诊断 | 五类卡点定位 | 精确到"第几步、什么类型的错误" |
| 干预 | 针对性纠错 | 指出方向，不给正确算式 |
| 复盘 | 沉淀可迁移方法 | 从具体题提炼通用策略 |

诊断发现没懂？回到"练"出一道新题重新走，最多循环两轮。

## 五类卡点诊断

按"越根本越先查"的顺序诊断（命中即归类）：

| 类型 | 典型表现 |
|------|---------|
| 无从下手 | 各步空着，全选"还没想好" |
| 审题理解错误 | 读错或看漏题干条件 |
| 方法/概念偏差 | 方法层出错：用错数量关系，或关系对但路径绕 |
| 过程跳步 | 方法路径都对，漏掉关键中间步骤 |
| 计算失误 | 方法全对，纯粹某步算错数 |

> **为什么不是六类**：「概念混淆」和「方法选择错误」要区分的是学生脑子里的理解状态，分步作答里往往看不出来，且两者的干预同为"补讲"。所以诊断层合成一类，"关系错 / 路径绕"的区分下沉到干预时看具体作答再判。
>
> **计算失误排最后**：只有方法、路径、步骤全对时才归它，避免把方法层问题误诊成粗心。

## 快速开始

### 安装

复制整个目录到你的 agent skills 路径：

```bash
cp -r math-tutor ~/.agents/skills/
```

支持 opencode、Claude Code、Cursor、WorkBuddy 等任何 agent 环境。

### 使用

对话中说：

> "教我这道题：鸡兔同笼，头10脚26，鸡和兔各几只？"

引擎会自动启动五步循环。

### 文件结构

```
math-tutor/
├── SKILL.md          # 行为规则（状态机 + 各阶段约束）
├── prompts.js        # 各阶段行为模板
├── turn.mjs          # 每轮入口：守卫校验 → 落盘 → 推进计数器 → 重渲染面板
├── render.mjs        # 教学面板渲染：state.turns → 完整 HTML
├── guard.mjs         # 运行时守卫：回复前校验教学红线
├── log.mjs           # 学情日志：REVIEW 后把 state 投影成一行 JSONL
├── setup.mjs         # 家长首次配置：环境检查 / 清理旧状态 / 安全网自测
└── problem-types/    # 题型骨架库（13 个，见下）
    └── _schema.md    # 如何编写新题型
```

零 npm 依赖，零 pip 依赖，零外部服务。

### 学情日志

每做完一道题（走完 REVIEW），`log.mjs` 会把这次辅导投影成一行 JSONL 追加到
`~/.math-tutor-log.jsonl`：卡在第几步、什么类型的卡点、追问了几次、换新题后能不能独立做对。

这个文件是跨题累积的，`setup.mjs` 清理旧状态时也不会动它。教学本身不读它——
它是留给学情分析用的数据源（本仓库不含分析端）。想看里面记了什么：

```bash
node log.mjs --dry-run    # 只打印投影结果，不写日志
```

一条记录 = **一次辅导**，不是一道题：`rounds[]` 里每条是一次诊断，全部是练习题，
学生带来的原题只被讲解、从没被独立作答过。要数做了几道题得按 `problem_index` 去重。

### 题型库

覆盖小学高年级（五、六年级）常见应用题：

| 类别 | 题型 |
|------|------|
| 假设与推理 | 鸡兔同笼、盈亏问题 |
| 行程 | 相遇问题、追及问题、流水行船 |
| 倍数与比 | 和差倍问题、按比例分配、年龄问题 |
| 分数与平均 | 分数应用题、平均数问题、归一问题 |
| 工程与规律 | 工程问题、周期问题 |

**为什么集中在五、六年级**：骨架机制要求题目有"关键洞察 + 3-5 步推理"的结构。
三四年级题目一两步就完，五类卡点里只有「计算失误」用得上，机制大半空转；
初中解法收敛到列方程，题型差异被抹平，且几何看图题本 skill 不支持。

AI 不手写 HTML：它每轮只产出一条结构化 turn，面板由 `render.mjs` 从 `state.turns`
确定性渲染。所以教学历史结构上不可能被压缩或丢失，泄底的文本也进不了页面
（守卫不过就整轮不落盘）。

## 工作原理

1. **SETUP**：分类题目 → 加载/生成解题骨架 → 创建教学面板
2. **EXPLAIN**：每轮输出一张 HTML 卡片（含 SVG 配图）+ chat 引导提问
3. **PRACTICE**：分步选择题/填空题，HTML 表单一次性提交
4. **DIAGNOSE**：对照标准答案逐步检查，定位卡点类型
5. **INTERVENE**：针对性引导，纠正后出新题验证迁移
6. **REVIEW**：复盘卡片（总结 + 下次怎么想 + 鼓励）

### 教学面板

`~/Downloads/math-tutor-card.html`，由 `render.mjs` 从 `state.turns` 全量重渲染，包含：
- SVG 可视化配图（圆点/箭头/标注）
- 进度条
- 完整对话历史（结构上不可压缩——AI 不重写页面，只追加 turn）
- 练习表单（提交后 JSON 复制到剪贴板；学生正在打字时自动跳过刷新，不打断）

学生浏览器打开面板，在 agent 对话中互动。

## 添加新题型

参考 `problem-types/_schema.md`，创建 `.md` 文件定义：

- 分类信号（怎么识别这类题）
- 解题骨架（3-5步，每步标注核心点、练习类型、讲解红线）
- 题型特有注意点

骨架是讲解、练习、复盘的单一事实源，错误骨架比没骨架更危险——写完先自己跑一遍完整流程。

## 验证改动

没有测试框架，**每个脚本自带 `--selftest`，这就是唯一的测试入口**：

```bash
for f in guard render turn log; do
  node $f.mjs --selftest >/dev/null && echo "PASS $f" || echo "FAIL $f"
done
```

共 149 项（guard 48 / render 20 / turn 52 / log 29）。想看逐条 case 就别重定向 stdout。
`setup.mjs` 没有自己的自测，它做的是环境检查——顺带把上面四个脚本的自测跑一遍。
`guard.mjs` 不过会直接叫停（"先别给孩子用"，泄底关卡失效），`turn.mjs` 不过也阻断（每轮都要走它）；
`render.mjs`、`log.mjs` 只警告，因为坏了不会泄露答案，只是面板画不出来或日志记不上。

改守卫尤其要跑：它的误报会让整局教学被拦住（讲份数、复述题干这类正常话被当成泄底），
漏检则把答案漏给学生。两类失效都不会报错，只能靠自测撞出来。

不落盘地手动验证：

```bash
node turn.mjs --turn-file /tmp/turn.json --dry-run   # 只校验+渲染，不写 state
node render.mjs                                      # 从当前 state 重渲染面板
```

`guard.mjs` / `turn.mjs` / `setup.mjs` 有 `--help`，比读源码快（`render.mjs`、`log.mjs` 的用法看文件头注释）。
退出码统一：`0` 成功 / `1` 命中红线、自测失败或缺 state / `2` 用法错误。

## 已知限制

- 仅支持**纯文字题**（条件可用文字完整描述）
- 不支持看图题（几何图形、图表数据、空间推理）
- SVG 配图为教学示意，不还原原题图片
